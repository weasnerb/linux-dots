# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Personal Linux dotfiles (Arch, Hyprland on Wayland, session managed by uwsm). There is no build, lint, or test suite. Everything under `src/` mirrors `$HOME`: `src/.config/foo` is symlinked to `~/.config/foo`.

## Installer

`./installer.py install` / `./installer.py uninstall` (run from the repo root; it uses `Path.cwd()/src`). It also takes `--all` to skip prompts.

- It walks `src/` and treats any file starting with `.`, or anything whose parent directory starts with `.`, as a config. So top-level dotfiles (`src/.zshrc`) and the direct children of `src/.config/` (whole directories like `hypr/`, `nvim/`) are each symlinked as a unit; nothing deeper is linked separately.
- Existing targets are moved to `<name>.bak` (recursively, `.bak.bak`) on install and restored on uninstall.
- Passing explicit config names (`install <path>`) is unfinished: it only prints "Should install", with `# INSTALL` left as a TODO.
- **Exception: `PER_FILE_DIRS` (currently `.config/systemd`) are linked one file at a time**, creating real parent directories as needed. `~/.config/systemd/user` also holds systemd's own enablement symlinks (`*.wants/`), so linking the whole directory would move them aside and disable every user unit. Enable the units with `systemctl --user enable <unit>` after installing.

## Session (uwsm)

Hyprland runs under uwsm, so autostart is systemd user units wanted by `graphical-session.target`, not `exec` calls in the Hyprland config:

- `systemd/user/import-gsettings.service` and `polkit-gnome-authentication-agent-1.service` are ours.
- `hyprpaper.service` and `waybar.service` ship with their packages; `systemd/user/waybar.service.d/uwsm.conf` is a drop-in for uwsm.
- `uwsm/env` is the session environment. uwsm only sources POSIX sh profiles, so PATH additions from `.zprofile` are mirrored there.
- **Restart waybar with `systemctl --user restart waybar`** (config-only changes: `systemctl --user reload waybar`). Killing and relaunching it by hand makes the service respawn a second bar and orphans the custom-module scripts.

## Hyprland

The legacy hyprlang `.conf` files were removed; config is now Lua (`hl.*` API).

- `src/.config/hypr/hyprland.lua` holds the shared config: binds, animations and appearance. Its autostart block only runs when Hyprland is *not* under uwsm, as a fallback for the plain ly session. The check reads `/proc/self/cgroup` for `wayland-wm@`; don't switch it to `INVOCATION_ID`, which ly (itself `ly@ttyN.service`) passes down to every session it starts.
- Per-machine settings (monitors, workspaces, brightness, and similar) live in `hypr/brian-arch/config.lua` and `hypr/brian-desktop-arch/config.lua`. `hyprland.lua` loads them via `require("current-computer.config")`. `current-computer` is a **gitignored symlink** created by hand on each machine (`ln -s ./brian-arch ./current-computer` inside `~/.config/hypr`).
- Colors come from `~/.cache/wal/colors-hypr.lua`, generated by pywal from the template `src/.config/wal/templates/colors-hypr.lua`. Run `wal -R` to regenerate. Any Lua error aborts the whole config (no binds at all), so this file and the per-machine `require` are loaded through `pcall`: if missing, Hyprland uses fallback colors / skips the machine config and shows an on-screen warning.
- The Lua loader is strict: unknown keysyms make reload fail. Some old `.conf` binds were silently invalid; see the NOTE comments in `hyprland.lua` before "fixing" the screenshot or mic-mute binds.
- Bind options go in a third table argument, e.g. `{ locked = true, repeating = true }` (work on the lock screen / repeat while held). `/usr/share/hypr/hyprland.lua` is the upstream example config and `/usr/share/hypr/stubs/hl.meta.lua` documents the API.
- Helper scripts live in `hypr/scripts/`: `volume.sh` (wpctl + dunst volume popup), `powermenu.sh` (fuzzel dmenu power menu), `import-gsettings.sh` (run by its systemd unit), `makemywall.sh` (wallpaper padding tool; likely the only surviving copy, don't delete).
- Launcher is fuzzel (`fuzzel/fuzzel.ini`); it prefixes launches with `uwsm app --` itself.

## Waybar

`waybar/config` + `waybar/style.css`, with custom modules in `waybar/custom-modules/`:

- `performance.py`: long-running GLib loop. Icon is the tlp-pd power profile (PPD D-Bus API); turns red at 80%+ CPU or RAM; tooltip has per-core CPU and RAM. Waybar runs one copy per monitor: left-click `pkill -USR1`s all of them (the pattern in `config` must match `PROCESS_PATTERN`), every copy updates its icon at once, and only the copy holding `$XDG_RUNTIME_DIR/waybar-performance.lock` (flock) switches the profile and handles low-battery notifications. Battery thresholds `BATTERY_WARNING`/`BATTERY_CRITICAL` must match the battery module's `states` in `config`. Exceptions inside GLib callbacks are only logged, so it exits explicitly on a broken pipe to avoid orphans.
- `media.py`: any MPRIS player; shows the most recently active one and records its instance name in `$XDG_RUNTIME_DIR/waybar-media-player` so the click actions (`playerctl -p`) control that same player. Falls back to another player when one closes.
- `tailscale.py` (+ `tailscale-menu.xml` for the right-click menu). Transition notifications are guarded by an flock so only one copy (of one per monitor) sends them; a connect/disconnect started from the module is marked as expected so it isn't announced as a critical alert.
- Glyphs are Material Design Icons. `style.css` lists `"Material Design Icons"` **first**, then `"MesloLGS NF"` for text. MDI has no letters, digits or spaces, so text falls through to Meslo; but Meslo (a Nerd Font) also has the MDI icons, and its scaling renders narrow ones oversized, so it must never come first.
- `waybar/.gitignore` ignores `__pycache__/` and `*.bak-*` backups.

## Other configs

- Neovim (`src/.config/nvim/`): entry `init.lua` requires `lua/main` (`set`, `remap`, `package-manager`), with per-plugin setup in `after/plugin/`. `lazy-lock.json` is gitignored.
- wal templates in `src/.config/wal/templates/` generate colors for GTK3 (waybar imports it), fuzzel, hyprpaper and hypr.
- `.zshrc` lazy-loads nvm via stub functions (sourcing it eagerly cost ~520 ms per shell).
