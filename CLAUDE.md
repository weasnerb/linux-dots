# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Personal Linux dotfiles (Arch, Hyprland on Wayland, session managed by uwsm). There is no build, lint, or test suite. Everything under `src/` mirrors `$HOME`: `src/.config/foo` is symlinked to `~/.config/foo`.

## Installer

`./installer.py install` / `./installer.py uninstall` (run from the repo root; it uses `Path.cwd()/src`). It also takes `--all` to skip prompts.

- It walks `src/` and treats any file starting with `.`, or anything whose parent directory starts with `.`, as a config. So top-level dotfiles (`src/.zshrc`) and the direct children of `src/.config/` (whole directories like `hypr/`, `nvim/`) are each symlinked as a unit; nothing deeper is linked separately.
- Existing targets are moved to `<name>.bak` (recursively, `.bak.bak`) on install and restored on uninstall.
- Passing explicit config names (`install <path>`) is unfinished: it only prints "Should install", with `# INSTALL` left as a TODO.
- **Exception: `src/.config/systemd/` must not be installed as a whole directory.** `~/.config/systemd/user` also holds systemd's own enablement symlinks (`*.wants/`), so the repo's unit files are symlinked into it one file at a time by hand (the `waybar.service.d/` drop-in directory is a real directory with the `.conf` symlinked). Enable them with `systemctl --user enable <unit>` afterwards.

## Session (uwsm)

Hyprland runs under uwsm, so autostart is systemd user units wanted by `graphical-session.target`, not `exec` calls in the Hyprland config:

- `systemd/user/import-gsettings.service` and `polkit-gnome-authentication-agent-1.service` are ours.
- `hyprpaper.service` and `waybar.service` ship with their packages; `systemd/user/waybar.service.d/uwsm.conf` is a drop-in for uwsm.
- `uwsm/env` is the session environment. uwsm only sources POSIX sh profiles, so PATH additions from `.zprofile` are mirrored there.
- **Restart waybar with `systemctl --user restart waybar`** (config-only changes: `systemctl --user reload waybar`). Killing and relaunching it by hand makes the service respawn a second bar and orphans the custom-module scripts.

## Hyprland (branch `hyprland-lua-migration`)

The legacy hyprlang `.conf` files were removed; config is now Lua (`hl.*` API).

- `src/.config/hypr/hyprland.lua` holds the shared config: binds, animations and appearance. Its autostart block only runs when Hyprland is *not* under uwsm (checked via `INVOCATION_ID`), as a fallback for a plain session.
- Per-machine settings (monitors, workspaces, brightness, and similar) live in `hypr/brian-arch/config.lua` and `hypr/brian-desktop-arch/config.lua`. `hyprland.lua` loads them via `require("current-computer.config")`. `current-computer` is a **gitignored symlink** created by hand on each machine (`ln -s ./brian-arch ./current-computer` inside `~/.config/hypr`).
- Colors come from `~/.cache/wal/colors-hypr.lua`, generated by pywal from the template `src/.config/wal/templates/colors-hypr.lua`. Run `wal -R` to regenerate. The hypr config will fail to load if the cache file is missing.
- The Lua loader is strict: unknown keysyms make reload fail. Some old `.conf` binds were silently invalid; see the NOTE comments in `hyprland.lua` before "fixing" the screenshot or mic-mute binds.
- Bind options go in a third table argument, e.g. `{ locked = true, repeating = true }` (work on the lock screen / repeat while held). `/usr/share/hypr/hyprland.lua` is the upstream example config and `/usr/share/hypr/stubs/hl.meta.lua` documents the API.
- Helper scripts live in `hypr/scripts/`: `volume.sh` (wpctl + dunst volume popup), `powermenu.sh` (fuzzel dmenu power menu), `keyboard_backlight.py`, `import-gsettings.sh` (run by its systemd unit), `makemywall.sh` (wallpaper padding tool; likely the only surviving copy, don't delete).
- Launcher is fuzzel (`fuzzel/fuzzel.ini`); it prefixes launches with `uwsm app --` itself.

## Waybar

`waybar/config` + `waybar/style.css`, with custom modules in `waybar/custom-modules/`:

- `performance.py`: long-running GLib loop. Icon is the tlp-pd power profile (PPD D-Bus API); turns red at 80%+ CPU or RAM; tooltip has per-core CPU and RAM. Left-click sends SIGUSR1 (pid in `$XDG_RUNTIME_DIR/waybar-performance.pid`) to cycle profiles in-process. It also sends low-battery notifications and switches to power saver at `BATTERY_WARNING`/`BATTERY_CRITICAL`, which must match the battery module's `states` in `config`. Exceptions inside GLib callbacks are only logged, so it exits explicitly on a broken pipe to avoid orphans.
- `tailscale.py` (+ `tailscale-menu.xml` for the right-click menu) and `media.py` (playerctl).
- Glyphs are Material Design Icons. `style.css` lists `"Material Design Icons"` right after Roboto so they don't fall back to MesloLGS NF, whose Nerd Font scaling renders narrow icons oversized.
- `waybar/.gitignore` ignores `__pycache__/` and `*.bak-*` backups.

## Other configs

- Neovim (`src/.config/nvim/`): entry `init.lua` requires `lua/main` (`set`, `remap`, `package-manager`), with per-plugin setup in `after/plugin/`. `lazy-lock.json` is gitignored.
- wal templates in `src/.config/wal/templates/` generate colors for GTK3 (waybar imports it), fuzzel, hyprpaper and hypr.
- `.zshrc` lazy-loads nvm via stub functions (sourcing it eagerly cost ~520 ms per shell).
